# Yokai.exe — Economy & Combat API Contract V1.1

This contract is subordinate to live server configs and the Master GDD. Global Economy V1 documents are reference-only.

## Authentication

Every write endpoint requires a server-authenticated player derived from validated Telegram `initData`. The player ID is never accepted from an untrusted request body.

## Start Rift

`POST /api/rifts/start`

```json
{
  "riftId": 1,
  "mealItemId": "ramen_attack_01",
  "drinkItemId": "soda_ap_01",
  "weaponId": "training_katana",
  "idempotencyKey": "rift:start:<clientActionId>"
}
```

The server atomically:

1. resolves current economy/combat/content configs;
2. checks Rift availability;
3. locks inventory units;
4. reserves consumables so no second run can use them;
5. creates the run with immutable config versions;
6. returns the authoritative run snapshot.

## Combat action

`POST /api/rifts/action`

```json
{
  "runId": "uuid",
  "actionId": "client-unique-action-id",
  "actionType": "SEAL",
  "targetId": "oni-404"
}
```

The server validates phase, AP, HP, cooldowns, target and inventory. For `SEAL`, the talisman is consumed immediately when the action is accepted, before the success roll. The action key is idempotent.

The response contains authoritative combat state and any confirmed Oni reward. The client does not send outcome, damage, `pendingCoins` or reward amounts.

## Oni reward

After a server-confirmed Oni defeat, the server calculates:

```text
floor(baseReward × RiftOfDay × antiFarm × event)
```

The result is appended to the run and added to `run.pendingCoins`. It is not added directly to the wallet.

Recommended key:

```text
oni:reward:<playerId>:<runId>:<oniIndex>
```

## Settle Rift

`POST /api/rifts/settle`

```json
{
  "runId": "uuid",
  "outcome": "COMPLETED",
  "idempotencyKey": "rift:settle:<clientActionId>"
}
```

The server independently verifies the requested outcome from persisted combat actions.

Settlement:

- `COMPLETED`: 100% of `pendingCoins`;
- `DEFEATED`: 100%;
- `ABANDONED`: 50%, rounded down;
- `TECHNICAL_FAILURE`: deterministic recovery or auditable compensation.

First Clear is a separate ledger transaction and is only eligible after `COMPLETED`.

Response:

```json
{
  "run": {
    "runId": "uuid",
    "status": "COMPLETED",
    "pendingCoins": 120,
    "settledCoins": 120,
    "firstClearCoins": 60,
    "economyConfigVersion": "economy-1.1.0",
    "combatConfigVersion": "combat-1.1.0",
    "contentConfigVersion": "content-1.1.0"
  },
  "walletBalance": 1280
}
```

## Contract claim

`POST /api/contracts/claim`

```json
{
  "contractId": "daily_yokai_5",
  "cycleKey": "2026-06-28",
  "idempotencyKey": "contract:claim:<clientActionId>"
}
```

The server derives and verifies the UTC cycle. The canonical stored key includes:

```text
contract:claim:<playerId>:<contractId>:<cycleKey>
```

Claim state and wallet grant commit atomically.

## Daily reset

All daily cycle keys are generated by the server at `00:00 UTC`. Client locale and device clock do not determine eligibility.

## Catalogs

Stars products, weapon prices, upgrade prices, Rift values, event multipliers and contract definitions come from live server configs. Client constants are preview fallbacks only.
